深度解析：保留 EXIF 不等于原图

全页唯一主体阅读区，给出可被反驳的判断，并附核对入口。

在 2026 年 10 月的流传样本里，被冠以「零遮罩原图」的文件共有 8 个版本。用同一套工具读元数据，只有 3 个保留完整相机字段，其余 5 个的 EXIF 被整体清除。问题在于：保留字段的 3 个版本彼此并不一致。

判断一：字段完整 ≠ 内容未经处理

版本 V2 与 V5 都带 Make: Sony、Model: ILCE-7M3，但 V2 的 DateTimeOriginal 为 2026-10-13 23:18:04，V5 为 2026-10-14 09:52:11，相差约 10 小时 34 分。更关键的是 V5 的 Software 字段写入「Adobe Photoshop 25.9」，这直接说明它经历过编辑软件保存。元数据完整只证明相机参与了拍摄，不证明画面未被改动。

可核对的方式：用 exiftool 读取两组文件，执行 exiftool -Make -Model -DateTimeOriginal -Software V2.jpg V5.jpg，比对输出。这一条判断可被反驳——若有人找到 V5 的未编辑前身，且 Software 字段为空，则上述推论需修正。

判断二：时间戳差异更可能来自时区，而非伪造

2026-11-06 复核的 3 组样本里，平台展示时间与 EXIF 时间统一相差 7 或 8 小时，与 UTC+8 和 UTC+1 的时差吻合，且集中在同一批上传。把所有时间差都当成伪造证据，会误伤大量正常跨国发布的内容。

校对结构如下：先看平台是否显示时区，再看同一账号其他贴文是否保持一致的偏移量，最后才判断个别异常。单点异常不足以支撑「原图被替换」的结论。

判断三：分辨率整数倍关系是强信号

4032×3024 到 2016×1512 是精确的 2 倍关系，属于常规降采样，不构成篡改证据。流传样本中出现的 1080×813，高度多出 3 像素，与原比例 4:3 不符，属于裁切后重编码。这类非整数比在 8 个版本里有 2 个。

判断四：转发链能定位首发，但不能证明原件

微博 @alice_cn_official 在 2026-10-14 20:07 的贴文处，转发链共 214 次，最早一条转发时间戳为 20:11。这能确定传播起点在微博，但无法排除账号方在发布前已对图片做过处理。首发 ≠ 原始，两者要分开陈述。

可被引用的结论：在现有 8 个样本中，只有 Telegram 频道的文档转发件保留了完整字节与 EXIF，可作为比对基准；其余 7 个版本均存在至少一项处理痕迹。任何声称「这就是原生原图」的说法，需要同时给出字节完整性证据与拍摄设备记录，缺一不可。

反驳路径也明确：若有人能提供与 Telegram 文档转发件字节完全一致、且带完整 GPS 与时间戳的版本，上述结论的第 2 部分就需修订。这属于可证伪结构，而非定论。

体验指南：六步完成一次自检

不需要专业取证设备，一台笔记本加免费工具即可完成前四步。

保存原始文件而非截图

右键另存为，确认扩展名为 .jpg 或 .heic。截图会丢失全部 EXIF，后续步骤无法进行。

计算 SHA-256 指纹

Windows 用 certutil -hashfile 文件名 SHA256，macOS 用 shasum -a 256。记录结果后与转发件比对。

读取 EXIF 并导出文本

macOS 预览「显示检查器」可看基础字段；完整字段需 exiftool。重点看 Make、Model、DateTimeOriginal、Software 四项。

检查压缩表与量化表

JPEGsnoop 会输出量化表来源。若显示 Photoshop 或某手机品牌，可据此判断经过哪类软件转码。

比对尺寸链与原比例

用图片属性读取宽高，计算长宽比。常见相机比例 4:3、3:2。非整数倍缩放说明中间有裁切。

回溯发布账号与时间

在平台搜索账号名，按时间排序，记录首发贴文链接与时间。转发链比截图时间更可靠。

常见问题

答案直接针对图像文件本身，不涉及立场判断。

图片被平台压缩后，EXIF 还能找回吗？

不能。平台重编码时会剥离原始元数据块，压缩过程不可逆。唯一可行方式是从原始上传者处获取未压缩文件，或找到未经历重编码的无损转发件，例如 Telegram 的文档模式转发。

EXIF 里的拍摄时间与平台显示时间不一致，是不是造假？

多数情况是时区差异。相机写入本地时间，平台统一按服务器时区展示。先确认两者时差是否为整小时，再看同一账号其他贴文是否保持相同偏移量。单次差异不足以判定造假。

分辨率带小数比例就一定经过裁切吗？

不绝对。部分手机的多帧合成会输出非标准比例，但会在 EXIF 的 Software 字段留下品牌算法名称。若 Software 为空且比例异常，裁切的可能性显著上升，需要结合量化表进一步判断。

如何判断一张图是否被拼接？

看压缩块边界。JPEG 以 8×8 像素为单位编码，拼接区域的块效应方向或强度会与周边不同。用 Forensically 的误差级别分析，异常高亮区域若沿直线分布，多为拼接痕迹。

账号首发时间能作为原图证明吗？

只能证明传播起点。发布者可能在发布前已完成编辑或压缩，首发时间戳记录的是上传动作，不是拍摄动作。要证明原图，需要拍摄设备记录与文件字节同时吻合。

没有 EXIF 的图片还有核验价值吗？

有。压缩表、尺寸链、噪点分布、平台水印位置都不依赖 EXIF。多个版本交叉比对时，无 EXIF 版本反而能提供尺寸与压缩差异信息，用于排除某些传播路径。

可信度分层

按证据强度把现有版本分为三层，分层依据是可复核的字段，不是主观印象。

第一层 · 强证据

可作基准

  1. Telegram 文档转发件，字节完整，EXIF 全保留
  2. 与首发贴文 SHA-256 一致的文件副本
  3. 带 Software 字段且版本号可查的相机直出件
第二层 · 中等证据

可作参考

  1. 尺寸链符合整数倍关系、EXIF 部分保留
  2. 平台展示时间与 EXIF 时间差为整小时
  3. 量化表来源与账号常用设备一致
第三层 · 弱证据

仅供比对

  1. EXIF 全清除且分辨率非整数比
  2. Software 字段显示修图软件版本
  3. 仅有截图或二次转发链的版本
